# 项目与素材管理

剪多了就会发现：素材、导出文件、确认过的样式、踩过的坑，如果每个视频都各存一份，磁盘很快被占满，而且下一条视频想复用时根本找不到。所以要从第一条视频开始就分两个层次管理。

## 原则

1. **大文件只存一处。** 下载的素材、音乐、音效、确认过的样式，都放进**全局库**；项目只引用，不复制。
2. **项目文件夹只放本片专属的东西**：原片（或原片路径）、逐字稿、方案、状态、各版成片。
3. **先查库，再找料；定稿后，回写库。** 查库省下的是搜索、下载、授权检查的时间和 token；回写让下一条视频直接变快。
4. **库和项目放在空间充足的盘**，每次定稿报告占用，清理前列清单让用户确认。

## 全局库：跨视频共用

位置由用户决定，记在每个项目的 `PREFS.md` 里。用 `scripts/init_workspace.py library <路径>` 一键建好。

```
<库>/
├─ README.md
├─ lessons.md              你自己的经验库（skill 自带的是通用种子，个人的写这里）
├─ styles/                 已确认的样式风格
│  ├─ STYLES.md            索引：样式、状态（已确认 / 已否决 / 候选）、日期、原话
│  ├─ _candidates/         小样阶段的候选，等用户点头
│  └─ <style_id>/          每个已确认的样式：preview 预览图 + spec.md + 源码或参数
├─ assets/
│  ├─ ASSET_LEDGER.csv     全库素材台账
│  ├─ footage/ images/ music/ sfx/
│  ├─ _inbox/<任务号>/     执行 Agent 刚交付的，等审核
│  └─ _rejected/           审核没通过的（清理前请用户确认）
└─ tools/                  可复用的脚本（质检扫描等）
```

**ASSET_LEDGER.csv 列：**
`asset_id,kind,file,desc,tags,source,source_url,license,author,attribution_required,spec,sha1,added,used_in,status`

- `asset_id` 带前缀：`FT-`（实拍）`IMG-` `MU-`（音乐）`SFX-`
- `file` 用相对于库根目录的路径
- `tags` 写主题和画面特征，方便下次检索（例如：教堂, 室内, 暖光）
- `attribution_required` 为 yes 的，发布简介必须署名
- `used_in` 记录用过它的项目（分号分隔）
- `status`：`inbox` / `accepted` / `rejected`

**STYLES.md 列：**
`style_id,name,kind,status,date,project,files,note`

- `kind`：字幕 / 经文或引用卡 / 章节卡 / 动效图形 / 调色 / 封面版式 / 配乐风格
- `note` 里写用户的原话（"样式通过了""不要旁注"），这是下次沿用或避开的依据

## 项目文件夹：每个视频一个

用 `scripts/init_workspace.py project <项目根目录> <标题>` 建好。

```
<项目根>/<YYYYMMDD>_<标题>/
├─ PROJECT.md              库的位置、平台、当前版本（一页）
├─ 00_source/              SOURCE.md 记录原片路径；大文件不复制
├─ 01_transcript/          逐字稿、粗剪表
├─ 02_plan/                PREFS.md、WORKFLOW_STATE.md、分镜表、标题与简介草案
├─ 03_assets/              USED.csv：本片用了库里哪些 asset_id、在哪个时间码
│                          （只有本片专属的生成图、定制素材才放文件）
├─ 04_work/                工程文件、stems、中间产物（定稿后清理）
├─ 05_deliver/             成片：一个版本一个文件夹
│  ├─ v1_<说明>/           视频 + 字幕 + 封面 + 标题简介 + 署名 + 更新说明
│  └─ _待删除/             试导出、有问题的废片，用户确认后清空
└─ 06_qa/                  质检报告、接触表、逐镜头审核表
```

成片只有一个位置；分享给别人（上传云盘）的就是 `05_deliver/` 下的版本文件夹。剪辑软件的导出路径要显式指到这里或 `04_work/`，不要用默认的系统盘目录。

## 各步骤怎么用库

| 步骤 | 动作 |
|---|---|
| 1 接活 | 找到库（没有就问用户放哪个盘并建好）；读 `STYLES.md`：**已确认的样式默认沿用，已否决的不再提议**；读库里的 `lessons.md`；建项目文件夹 |
| 6 方案 | 分镜表里的 B-roll 先在 `ASSET_LEDGER.csv` 里按标签和用途找，命中的直接标 asset_id |
| 7 找料 | 只为没命中的派执行 Agent，**输出目录指到 `assets/_inbox/<任务号>/`**；审核通过的移入分类目录并写台账，没通过的移到 `_rejected/` |
| 8 小样 | 新样式的小样放 `styles/_candidates/`；点头后移到 `styles/<style_id>/` 并登记；被否决的也登记，写明原因 |
| 9 上轨 | 剪辑软件直接引用库里的素材路径，不复制进项目；`USED.csv` 记录用了哪些 |
| 12 出包 | 按下面的"回写清单"逐项做 |

## 回写清单（第 12 步，每条视频定稿后）

- [ ] 本片用到的素材：台账的 `used_in` 补上本项目
- [ ] 本片新下载的素材：已全部从 `_inbox` 入库或移到 `_rejected`
- [ ] 用户点头的新样式：入 `styles/` 并登记；被否决的也登记
- [ ] 本次审片意见：提炼成"原因 + 做法"，追加到库的 `lessons.md`（通用的坑也可以提交回 skill 的 `references/lessons.md`）
- [ ] CC-BY 等需要署名的素材与音乐：写进发布简介
- [ ] `WORKFLOW_STATE.md` 的锁定清单（已认可 / 已否决）更新
- [ ] 清理 `04_work/` 的中间文件（只保留最新两版混音 stems）：先列清单，用户确认再删
- [ ] 报告库和项目当前占用的磁盘空间

## 命名

- 项目：`YYYYMMDD_标题`
- 版本文件夹：`v1_粗剪`、`v2_修订`、`v3_终版`，同一个视频的所有版本放在同一个 `05_deliver/` 下
- 素材文件：`<asset_id>_<来源>_<简短描述>.<扩展名>`

## 为什么这样做

- 每个视频都往自己文件夹里塞一份素材，十条视频就是十份重复文件；放进库只存一份，台账负责告诉你它在哪、能不能商用、用在了哪。
- 样式和经验不挂在某个视频上，才能"确认一次，处处沿用"；这也是让模型越用越懂你的口味的地方。
- 库是最有价值的资产，建议提醒用户定期备份。
